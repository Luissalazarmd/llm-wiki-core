# El mapa no es una escalera de madurez

## Tres conexiones distintas

- **Este tema contiene estas notas:** el MOC [[examples/obsidian/Wiki/Maps/Sombras|Sombras y confort]] organiza un recorrido. K-Plex puede mostrarlo arriba y las notas debajo.
- **Esta idea se apoya en esta fuente:** [[examples/obsidian/Wiki/Concepts/Sintesis|La explicación]] cita un informe ficticio. Eso es procedencia, no una carpeta padre.
- **Esta explicación desarrolla una pregunta:** una Síntesis puede conectar Semillas sin que el número de enlaces la haga Evergreen.

## Abrir el mapa

Empieza por [[examples/obsidian/Wiki/Maps/Indice|Mi biblioteca]] y elige un recorrido: no necesitas comandos para leer. K-Plex puede ser tu centro visual; si no está abierto, **Focus active note in K-Plex** o **Open K-Plex** son vías opcionales. Puedes usar su panel lateral de lectura.

Para ver cómo Core resuelve sus identificadores sin reescribir fuentes, abre [[examples/obsidian/Navigation/Lectura|Selección de lectura proyectada]]. Parent/Children expresa organización; Evidence apoyo; Contrasts tensión; BuildsOn/DevelopedBy desarrollo. Los tipos, razones y versiones completos se conservan en el texto. Si una nota desempeña varios papeles, su posición no sustituye ese argumento. Al abrir el original, K-Plex vuelve a su vecindario de enlaces; esta selección no instala un mapa semántico automático de toda la biblioteca.

## Configuración opcional

La plantilla `kplex.example.json` contiene ajustes visuales y campos de navegación. No sobrescribas una configuración personal completa con ella. Sus tipos usan role, sus títulos usan title/Title/aliases. Las lentes de desarrollo y revisión anterior son opcionales; no crean tareas ni aprueban conocimiento.

K-Plex puede crear, editar o eliminar. Durante lectura, no uses esas acciones sobre originales o notas sin el proceso de revisión. Ningún CSS o nombre de vista impone una barrera de permisos.

## Trabajar con el Bibliotecario

Puedes pedir «explícame esta nota», «compara estas ideas» o «retomemos esta propuesta». El agente sigue [[AGENTS|la entrada autorizada]], [[Librarian Profile|el perfil único]] y [[docs/knowledge-workflow|el flujo de conocimiento]]; no necesita recorrer toda la biblioteca. La revisión del cambio concreto sigue [[docs/review-contract|su contrato]], no una etiqueta o un número del Home. El host debe poder identificar el objeto seleccionado; no se da por supuesto que el agente ve tu editor.
