# Optional Obsidian workbench

## Run safely

From the Core checkout, using the existing Python/PyYAML environment:

    PYTHONDONTWRITEBYTECODE=1 python3 scripts/obsidian_demo.py --output /an/authorized/absent/directory

The parent directory must already exist. The destination must be new, non-symlink and outside Core. The helper copies only the original example and allowlisted Core references, creates native test settings/CSS, and reprojects one bounded reading selection. It refuses overlays, copies no Git/private configuration or third-party plugins, and never reads or deploys a personal library. It is a fixture preparation tool, not a sandbox or general vault exporter.

Open the generated directory as a disposable vault and open `examples/obsidian/Home.md`. Existing Obsidian supports the native `.base` and `.canvas` surfaces. Testing/opening a fixture does not authorize changing another vault, Sync, accounts or plugin installations. No network imagery/fonts are used.

Alternatively, open this checkout in Obsidian and open the example Home, understanding that Obsidian may create local UI state in the checkout. The disposable path is preferred for testing. Do not use the example as a place to put private notes in a public repository.

## What is automatic

`Biblioteca.base` consults only the selected example source, proposal and knowledge paths. Panorama counts every matching file. Capture custody is determined before role, so a malformed Raw role never increments Wiki notes. Captures, notes and maps/indexes remain distinct; entity/project/diagram uses belong to notes. Atencion shows all Inbox proposals ordered by title. Keep only active proposals in that selected location through the library's permitted workflow; no review field or inferred acceptance is needed. Only Recientes is a labeled five-file sample. Madurez displays retained notes only; captures and organizational maps do not display idea development. Technical observations are available in the Base, not another permanent Home queue.

`Incorporaciones` groups documentary creation dates. Missing/conflicting/invalid dates have separate labels. This is not historical vault size, review events or every edit; real longitudinal measurement is not started. `Recientes` means last filesystem modification, not admission or learning.

The CSS makes native group summaries compact but does not change their data, permissions or source files. Full inventories are one click away. Without CSS the native tables remain readable. Without K-Plex there are ordinary explicit wikilinks. Without Obsidian read Home/Navigation and the canonical Markdown contracts.

The two main panels are stable callouts, not fixed grid rows or exact human heading strings. Complete proposals may scroll inside their panel; this is presentation height, not a query limit. Native DOM changes still require visual checks. The main map/reading entry is an ordinary link; plugin commands are optional. No specialist, personal manuscript or account belongs to this public example.

## K-Plex and relation meaning

K-Plex is optional and not bundled. The native minimal-fixture interface tested is 0.1.3 (minimum Obsidian 1.13). `kplex.example.json` is a small settings reference, not an overlay installer; merge only selected keys after inspecting current settings and obtaining permission. It contains no navigation history, personal paths or tokens.

The example now stores `up` wikilinks and body Evidence/Contrasts/BuildsOn declarations in original notes. K-Plex can navigate those originals directly; the strict reader projects the same declarations without a parallel edge store. Maps retain their authored reading arguments and inverses derive from `up`. The fixture's redundant generic link on its contrast pair was replaced by explanatory prose so it does not mask the tension in K-Plex.

The disposable reading view remains available. It prefers specific adapter fields over Related, while K-Plex itself can resolve conflicting native roles into its friend region. The reader reports multiple relation kinds for inspection; source presence and graph position do not prove scientific support. See native observations recorded in the later focused-fixture slice. These observations do not certify the revised full Home/Base/Canvas layout.

The host can reproject one selected view using `knowledge.py --root ROOT --focus ID --format markdown --typed-navigation`; it writes stdout only. The materializer prepares that selection for the example. Saving/refreshing a real library view is a separately authorized host operation outside Raw/Review/Wiki, not a watcher or a compulsory view per article. Only bundled synthetic fixtures were adapted; no personal capture is rewritten.

Read-only navigation is a usage policy; K-Plex and Bases retain editing capabilities. Do not treat inferred graph links as agreement, proof, consent or an accepted state. No Dataview, chart plugin, server or updater is required. Bases Chart remains a separately reviewed optional enhancement, not installed by this helper.

## Architecture Canvas

`Arquitectura.canvas` explains responsibilities, work, custody, independent dimensions, save boundaries and surfaces in six groups. File cards point to the existing canonical contracts and sections instead of copying profiles. Labels state what connections mean. It is documentation, not monitoring of running agents. Use Canvas's group navigation/zoom for detail; the full overview is not meant to make long contract prose readable at miniature scale.

Review short explanatory cards when contracts change; file references retain their source. A static JSON/link test is not GUI acceptance. Canvas connections do not create semantic K-Plex relationships or update review states.

## Adapt in place, after review

Keep the existing library root, authored notes, metadata and tools. Replace the three example scope prefixes in the Base with the actual selected source/proposal/knowledge paths and review all formula mappings. Handle created versus Created explicitly and preserve conflicts; do not rewrite captures to standardize dates. Keep Home and navigation views outside source/proposal/maintained-knowledge inventories. Adapt Canvas reference paths to that library's active contracts. Keep a single existing Home; no parallel operational vault.

Present exact Home/Base/Canvas/CSS/settings changes for actual review before deployment; preserve recovery, recheck base versions and avoid concurrent writes. This helper is not the Markdown plain writer and does not authenticate decisions. Source rights and plugin installation are separate gates. Core has no project redistribution license; optional third-party plugins retain their own licenses and are not shipped here.
