# Implementation

Use [tools](first-cut-tools.md), [acceptance](acceptance.md) and the [handoff](simplification-handoff.md).

## Prospective living-synthesis adoption

This phased plan uses the implemented optional
[living-synthesis profile](knowledge-workflow.md#optional-living-synthesis-profile)
and [MOC-scoped addresses](../examples/numbered-notes/README.md#moc-scoped-synthesis-addresses-optional).
The bounded numbering mechanics are implemented; no real-library migration or
owner-reviewed pilot is delivered. Follow
[progressive adoption](../skills/progressive-adoption/SKILL.md); preserve existing
folders, schemas, hosts, authorship, IDs, originals and stronger custody rules.
Each phase retains the previous phase's boundaries; broaden only by explicit choice.

### 1. Agree a bounded correspondence and profile

Select an authorized sample, useful question and stopping condition. Read local
rules; agree how existing locations serve Raw/Review/Wiki responsibilities without
moving material. Decide whether this scoped collection benefits from the profile,
how a thematic primary MOC is represented, and whether optional human addresses
can coexist with stable technical identities and existing history. Unknown is not
absent: inspect permitted evidence rather than infer free slots or missing maps.

Record content/custody decisions and actual writer capabilities. Do not bulk rewrite
sources, authorship, IDs, classifications or older approvals. Adopting the profile
approves neither individual notes nor wider access. If permissions or identity
constraints remain unresolved, keep affected changes as proposals.

### 2. Use the shared mechanism

Use [optional numbering commands](first-cut-tools.md#optional-living-synthesis-numbering)
inside the existing reader/proposal/check/save/recovery path, using the local
canonical writer where required. One deterministic module derives reservations
from scoped files; there is no separate counter, fifth skill, writer, service or
chat-ingestion channel. Its opt-in representation is an adapter, not a mandatory
schema or an automatic migration of existing IDs.

The mechanism prepares the complete candidate, primary MOC association
and proposed unused address **before** exact human review. Bind technical identity,
target/base versions, evidence versions and the authorized scope. Present full
creation content or exact update diff plus readable result, including map and
reference changes, under the [review contract](review-contract.md).

Immediately before permitted save, recheck identity, target/base, evidence,
permissions, custody and slot availability under local locking/conflict rules.
Stop on collision, stale input or any changed reviewed candidate; prepare a fresh
candidate and obtain fresh review, never silently substitute an address. Save only
through the permitted path, read back exact bytes and retrieve the result. Recovery
needs separate permission and current-version checks preserving later work. Missing
writers block dependent writes only; independent reading/proposals may continue.
Batch saves are sequential, not atomic. On a partial failure, inspect the reported
completed files and private records rather than replaying or silently renumbering.
Moves preserve stable paths and reserve prior addresses; unknown history or
unsupported reference/rename conventions block affected moves, not reading.

### 3. Retain one useful reviewed pilot

After local scope, representation and writer permission are established, reuse or propose one useful
synthesis and its existing or co-proposed thematic primary MOC. Integrate fragments,
section citations, tensions and questions into an explanation; leave originals
unchanged. Obtain the person's exact decision, then check/save/read back through
the same mechanism. Verify identity, links, address availability and recoverability;
assess usefulness with the person rather than equating structural success with
intellectual quality. A proposal-only rehearsal is not a saved human-review pilot.

### 4. Broaden through the same mechanism

Choose the next bounded content set and explicit custody/permission decisions.
Reuse the same mechanism for new syntheses, deliberate primary-MOC moves and
retirement; keep those operations distinct. Do not recode secondary references or
mass-migrate historical work. Pause affected writes on conflict, retain the useful
pilot and continue only independent permitted work.

For every phase, distinguish proposed, confirmed, saved and managed-approved.
Run affected [acceptance](acceptance.md) and link/identity checks; report failures,
limits and not-run checks. Static or synthetic checks establish neither scientific
validity, actual human approval nor native rendering. Verify optional host surfaces
separately before claiming integration; no universal Obsidian/K-Plex/Dataview setup
is required.
