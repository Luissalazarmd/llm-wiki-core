# Review and writer selection

## Common human-review loop

1. Bind target/absence, complete draft and exact original/evidence versions before the first library write.
2. Present full exact content for creation, or exact diff plus readable result for updates, with destination, rationale, removals and uncertainty; titles, paths, hashes or summaries alone are insufficient.
3. Obtain the actual person's decision through the host. Copied chat, model labels, metadata, checkboxes, hashes and commits cannot authenticate consent. Changed inputs/content require fresh confirmation.
4. Recheck versions, permission, recovery and conflicts immediately before saving; pause concurrent edits/sync. Unknown/unavailable writer means proposal-only.
5. Managed Wiki uses only its existing canonical writer with required authenticated decisions, locking, audit/replay and recovery. Core supplies none. Explicitly editable plain libraries use permitted tools or [plain mechanics](plain-saving.md); Git is optional history.
6. Save, read back exact bytes and distinguish proposed/confirmed/saved/managed-approved. Recover only with separate permission and current-version checks preserving later work.
7. Missing earlier presentation needs post-save review, never retroactive certification or deletion/recreation. Capture follows [admission](raw-admission.md); [AGENTS](../AGENTS.md) governs external actions.
