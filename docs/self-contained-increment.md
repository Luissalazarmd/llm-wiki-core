# Current handoff: engine-agnostic Core v0.1

## Product decision

The user chose **Bibliotecario skills on the existing agent host**, not another engine. Core retains the philosophy Raw → Review → Wiki as source preservation, reviewable elaboration and maintained knowledge. These are logical responsibilities; directory names, flat/grouped organization and existing library protocols remain configurable. No copied library, compulsory metadata or extra bot/server/database.

AGENTS is the single progressive entry. One canonical profile, three action skills (read/connect, capture, review/save), optional personal configuration and small original helpers. The same host can also coordinate as Orquestador. Keep role, maturity and review independent; a YAML label or packet hash never authenticates approval. Ontology 1.1 expresses authority as actual host confirmation plus library policy, with all existing vocabularies unchanged.

## Removal of the old integration

The product no longer ships the vendor installer, private file manifest, vendor review adapter, private-input installer/smoke suite, obsolete engine configuration or integration handoffs. Before removal, the full non-Git working tree was copied outside the repository with a verified SHA-256 manifest: 51 files. Nine integration-specific files retired. No Git history rewritten, vault changed or dependency installed.

The resguard and its manifest remain in the owner's private local workspace, outside publication. This is preservation of original experiment files, not an active package or runtime authority. Future clones need none of its files; tests do not skip a vendor module or require authorized private source inputs.

Known historical marker names remain in plain-writer refusal tests/code and defensive Git exclusions solely to prevent accidental editing/publication of an existing managed library. They install/import/call nothing. `canonical_engine` remains a generic configuration compatibility name for an externally supplied managed writer, not a particular engine dependency. Actual library rules still forbid bypassing that writer.

## Functional scope

- Scoped existing-library mapping of folders, notes, attachments and conventions; no attachment decoding or migration. Unknown metadata stays unknown; temporary path locators are not persistent IDs.
- Optional strict role/maturity/review validation and source-version/locator anchors. Locators/claims need actual source reading; structural checks are not truth validation.
- Bounded navigation and existing-target proposed diff with original/draft/evidence hashes. No network calls, model runtime, semantic synthesis service or persistent graph.
- Capture is a host-tool skill: duplicate/version checks, provenance, permitted create-only or existing managed capture tools. No capture runtime implemented by Core.
- Ordinary editing only with explicitly selected plain policy, actual host-delivered human confirmation, original/evidence/diff checks, private previous-byte recovery and exact result readback. Managed/unknown libraries keep their own writer or proposal-only.

## Limits and permissions

The helper assumes quiet cooperative single-writer ordinary editing; no atomic CAS, locking/fencing, signed decisions, multi-file transaction, full crash journal or authenticated managed apply. A record written before save does not prove successful application. Actual host confirmation is not provided by a script. A library's stronger requirements remain intact; unavailable writer blocks dependent saving, not reading.

New-note packet support, automatic capture, full Markdown dialect/alias/PDF decoding, GUI/voice integration and universal host adapters are absent. Skill Markdown read by an agent is not automatic native registration. The independent report validates its tested scope only; public redistribution rights and graphical integration were not evaluated. Original sources, quotes/identifiers and privacy/provider scope remain protected.

The owner explicitly authorized committing and publishing the reviewed original Core files to the existing public repository. Local backup/receipt paths were removed from this handoff; personal settings, source content, recovery records and the vault are not part of that authorization. No tagged release, visibility change, dependency installation or new delegated worker is included. Public visibility does not grant a redistribution license. The owner's vault and its existing engine were not accessed or altered by this increment. Technical independence is not legal clearance.
