# Agent-guided knowledge contract

The human supplies questions, corrections and acceptance, not directory choices or engine commands. The Bibliotecario discovers this contract from AGENTS and guides a small useful next step. Read [ontology](ontology.md) only for metadata/projection work and [review contract](review-contract.md) for canonical changes. No separate workflow database or role-profile copy.

## One growing library

Raw preserves captured inputs and versions. Review owns proposals. Wiki owns accepted derived knowledge. A source does not move between stages. An article/project selects existing sources and knowledge; it does not create a parallel thematic library. Do not create a concept, map, folder, diagram or checklist just because a source was captured.

Physical organization may be flat or grouped under existing stages. Honor an existing preference; choose flat by default. Ask about grouping only if it changes the person's work. Paths are locations, not semantic identities or review states. Reorganization of already referenced files is a separate reconciled change, never a silent move. Refer to one source capture from several projects; distinct evidence versions need distinct capture IDs, not duplicated indistinguishable copies.

For an existing library, these stages map to existing responsibilities; they are not mandatory folders or a migration prerequisite. Locate the actual library and its applicable AGENTS/rules before reading content. Do not replace those instructions with Core's, move originals or assume metadata matches the strict ontology. Existing-mode discovery preserves unknown role/maturity and uses temporary path locators. Require an explicit selected file/folder scope, not a whole-library scan by default.

Use [progressive adoption](../skills/progressive-adoption/SKILL.md) when the person requests help incorporating an existing selection: distinguish external originals, personal observations, prior syntheses and author drafts; propose a logical correspondence, then one useful reviewed update/reuse case in place. Mixed folders need explicit file-level custody, not blanket source classification. Mapping never certifies prior review or permission; ordinary reading remains available without adoption. Continue incrementally rather than forcing every imported item through a whole-library migration or treating authored knowledge as external Raw evidence.

A map is a useful note explaining a reading path, not a compulsory category container. Retain it only when it contributes beyond its links. Temporary article links can live in an existing authoring/project note; new folder trees and copied bibliographies are unnecessary. Private authoring placement and publishing permissions remain separate choices.

## Guided loop

1. **Understand:** identify the user's current question and authorized material. Continue with sensible defaults; ask only when ambiguity affects meaning, privacy, rights, cost or scope.
2. **Capture:** resolve source identity, provenance, reuse/quotation rights and data class. Find an existing capture first. Preserve original titles and quotes. New Raw requires an existing MOC → acyclic ancestor chain → declared root and tags from the library's taxonomy, checked before saving and on exact readback using [Raw admission](raw-admission.md). Do not auto-create a MOC or invent tags; missing classification means draft only. Check the actual permitted writer; missing capability blocks capture, not independent reading. Existing sources are not rewritten retroactively.
3. **Read:** use scoped existing discovery, or strict catalog for adapted metadata, to select a focal object. Open only relevant originals and justified neighbors. A map's links are candidates, not an instruction to read the whole collection. Ordinary wikilinks do not imply agreement or source support.
4. **Connect:** state why sources or ideas relate; distinguish grouping, source support, disagreement and interpretation. Metadata validation does not establish that a claim follows from a source. Check locators independently before making a factual proposal.
5. **Discuss:** explain differences and consequences in the user's language. “Show another way” explores; “change this” requests a revision; “accept this version” can become a decision only through the verified host and exact packet binding. Clarify “that one” when ambiguous. Do not ask the human to type commands or maintain metadata.
6. **Retain:** update/reuse existing knowledge before adding a note. Prepare only useful material under the library's review policy; no duplicate queue. The packet helper binds existing base/draft/evidence or explicit absent-target creation with `--create`, not semantic support or acceptance. Review/confirm a new derived note before its first library write; do not create an unreviewed placeholder. Managed libraries use the writer already permitted by their own rules; verify its availability without reconstructing a Core component. Explicitly editable plain libraries can use permitted tools after actual confirmation, precondition/evidence checks and private recovery/proposal preservation; the optional [plain helper](plain-saving.md) supports no-clobber creation and version-checked updates. Unknown permissions mean proposal-only; independent reading continues.
7. **Resume:** retain the question, object IDs/versions, actual decisions and next step in the existing authorized continuity authority. Do not mirror the vault into memory or create a second queue.

Initiative means noticing an unclear definition, relevant connection or missing evidence inside the current task. It does not mean processing the whole backlog, changing permissions, silently changing roles or launching permanent background work.

## Idea emergence

Human-facing maturity is **Semilla → Síntesis → Evergreen**, with technical values `seed`, `developing`, `evergreen`. This describes the development of an idea, not its folder, MOC membership, review decision or publication status. Raw originals remain unchanged: source captures feed thinking; the derived explanation matures. A capture is not automatically a new idea note. New exploratory derived ideas start as Semilla unless their complete proposed content already justifies a different maturity through explicit review; existing foreign notes remain unknown, not retroactively labeled seeds.

- **Semilla:** a bounded question, observation or hypothesis, with context, source/locator where applicable, and uncertainty. It may be well connected and still preliminary. Do not present a personal hypothesis as an empirical finding.
- **Síntesis:** an explanation that connects selected seeds/ideas and original evidence, makes its own organizing argument explicit, separates agreement from tension, and records unresolved gaps. It adds understanding rather than concatenating summaries. It can be retained for continued work without pretending to be consolidated.
- **Evergreen:** a clear, reusable explanation with checked load-bearing claims, explicit scope/limitations, examined counterevidence and no unresolved issue that defeats its central argument. Stability means a defensible explanation worth maintaining, not permanent truth or a fixed age. It can remain private and personal.

Follow this bounded procedure inside the current question:

1. Select only relevant existing ideas and originals; reuse an explanation before adding another note. Retain their identities/paths, versions and exact claim locators. Do not scan the whole backlog or require a fixed number of sources.
2. State the proposed emergent idea in one sentence and why the selected ideas contribute. Distinguish new inference from source claims; an MOC groups, a synthesis explains. Connecting several evergreen notes may produce a new Semilla rather than a higher-level certainty.
3. Develop the explanation: what follows, why, what conflicts, where it applies, and what remains unknown. Check comparable methods and alternative explanations. Trace factual claims back through derived notes to the relevant originals; a mature note's label is not independent evidence.
4. Explain the current and proposed maturity and the specific work that justifies it. This is not a source-count or link-count threshold, nor promotion by tags, MOC depth, text length or elapsed time. If unresolved gaps prevent consolidation, keep Síntesis; if the connection itself is exploratory, keep Semilla. Reuse the same derived note when the idea is continuous; a genuinely different argument may need a separately reviewed note, not a compulsory clone per stage.
5. Present exact content and any maturity change through review/save. Obtain actual confirmation of that version; recheck bound originals/idea notes and save only through the library's permitted writer. No automatic maturity or accepted-state changes. Core helpers validate bytes/dependencies, not the scientific quality of this judgment.
6. If new evidence undermines an explanation, show the affected claim and propose correction, reopening or a lower maturity with reasons. Preserve disagreement and previous content; never silently downgrade or repair Raw. No mechanical maturity state machine is introduced.

Keep rationale, lineage/locators and unresolved questions in the existing note/proposal, not a second registry or queue. Use the library's schema; no mandatory new fields or folders. Human review may accept a Semilla for retention; it does not make it Evergreen. Likewise Evergreen is not an authenticated decision. An article is an author-led editorial use of retained knowledge, not a fourth maturity stage: preserve authorship, private authoring placement and citations; publication permission is separate from note confirmation or maturity. No automatic manuscript generation, duplication of the library or publication.

This is a procedure for the existing agent's reasoning, not a semantic runtime bundled in Core. Contract tests can verify discovery and declared boundaries, while synthetic helper journeys verify binding/readback. Neither proves semantic judgment, actual human confirmation or every host's behavior; those need a separately observed task.

## Navigation and understanding

Markdown remains the content surface. A small Home may link the current work and canonical stage indexes; it must not duplicate contents or introduce another lifecycle.

The original read-only projector renders a bounded navigation selection to stdout. It can provide plain wikilinks and K-Plex's existing `Children` field in a disposable view; this is view grouping, not scientific ontology or a new canonical store. No plugin is required. Do not install/reconfigure plugins without permission. Saving a view is optional and must be outside managed Raw/Review/Wiki; never feed it back as source evidence. Do not accumulate a view per article/category by default.

K-Plex navigation must be tested in the actual host before calling it integrated. K-Plex has editing actions and no verified universal readonly lock. Do not edit/rename/delete managed notes or relationships from it. Excalidraw can illustrate a question when available and authorized; drawings do not establish evidence or approval. Voice is another input channel only when the host supplies the actual selected object and verified human event; no integration is inferred from documents.

## Non-clinical worked journey

A user captures two public reports about urban tree shade. The Bibliotecario keeps each original once in Raw and asks what the user wants to understand. It reads measurement methods, suggests comparing temperature outcomes and notes differences in location and time. A shared-topic link is grouping, not proof of comparable causal effects.

If an explanation of shade measurements is worth keeping, propose one reusable concept with exact source locators/versions. A user correction requires a revised diff and new confirmation. Managed libraries stop at the proposal until the required authenticated host is connected. Plain libraries may save through their allowed host tools after real user confirmation and recovery/version checks, without claiming canonical-engine acceptance. A future article links the retained concept instead of making its own copy.

## Boundaries of this increment

Guided contract, scoped discovery, optional ontology, navigation and existing/absent-target derived-note proposals are implemented without the private engine. AGENTS links four portable action skills selectively, including bounded progressive adoption; they use the existing host, not automatic native skill registration or a migration runtime. The optional plain helper adds precondition/evidence/diff checks, no-clobber creation and update recovery for explicitly editable notes only. Automated source capture, source-identity uniqueness, universal template validation, semantic model execution inside Core, authenticated approval, state transitions, canonical apply, graphical/voice sharing and universal host interoperability are not implemented. Agent reasoning/consent come from the host, not the CLI. See [current evidence](self-contained-increment.md).
