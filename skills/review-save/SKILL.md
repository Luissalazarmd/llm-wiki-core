# Review and save

Copied into a host? The links below resolve from `skills/review-save/` in the Core install that the
library rules locate ([hosts](../../docs/hosts.md)); read them there.

## When to Use

Retain a useful correction/proposal or recover an authorized edit.

## Procedure

1. Prepare complete content/evidence, reusing existing explanations. Apply the
   [citations and lean metadata policy](../../docs/knowledge-workflow.md#citations-and-lean-metadata);
   include the note's complete citations and actual consulted scope in the human preview.
   Flag every unchecked citation there, and [check current evidence](../../docs/knowledge-workflow.md#check-current-evidence)
   for states and for facts taken from a synthesis.
2. For [idea emergence](../../docs/knowledge-workflow.md#idea-emergence), explain current
   and proposed maturity; when new evidence undermines an argument, propose correction.
   An idea the owner states in conversation, with no original to cite, is an
   [owner-authored seed](../../docs/review-contract.md#owner-authored-seeds): draft it
   with `role: note`, `maturity: seed` and `origin: owner`, and prepare it with
   `--create --owner-authored`. Never cite unrelated evidence to satisfy the writer.
   One stated while [reading a queued document](../../docs/ingesta.md#the-reading-session)
   names the source and pages it arose from in its text.
3. If the bounded collection opts into [living-synthesis numbering](../../docs/first-cut-tools.md#optional-living-synthesis-numbering),
   prepare through the shared proposal path before review. Show every numbered
   draft/diff and companion map change; explicit primary moves retain the same ID,
   preserve referenced sections and reserve old addresses. Do not allocate manually
   or silently replace a reviewed address. Recheck the exact packet immediately
   before permitted saving; changed scope/base/evidence requires a fresh candidate
   and decision. Stop on partial batch save and inspect the reported private records.
4. Foreground the changed passage and reason in the main chat; keep technical
   hashes in helper operations. Explicitly explain changes to maturity, review,
   identity or provenance. Before confirmation, use an actually supported host
   presentation to make the full exact creation, or exact diff plus complete
   readable resulting version, accessible. Conversation alone is not a saved edit.
5. Perform the [review contract](../../docs/review-contract.md): actual decision,
   current inputs, permitted writer, recovery and exact readback.

## Pitfalls

[Plain mechanics](../../docs/plain-saving.md) authenticate no consent; missing writer
means proposal-only. A parked proposal is [custody](../../docs/review-contract.md#proposal-custody),
not acceptance: review its exact text as any other before saving. `origin: owner` is
only for what the owner personally stated: an agent's or third party's claim, a
specialist's proposal or a parked item never qualifies, and promoting such a seed
needs evidence. Drafts [write for the reader](../../docs/knowledge-workflow.md#write-for-the-reader),
without procedure. A canvas, Base or `role: view` page is a [view](../../docs/views.md): same
review, saved only with `view_write.py`, never holding a claim. Follow [AGENTS](../../AGENTS.md).

## Verification

Distinguish proposed, confirmed, saved and managed-approved. Verify the exact version;
fixture writes are not human decisions.
